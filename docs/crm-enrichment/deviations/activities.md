# Deviations — Activities

Where the Activities screen departs from `design-reference/sentral/project/Activities.dc.html`, and why. Same
columns as `DEVIATIONS.md`; the lead builder folds these in.

| ID | Where | Design | Built | Reason |
|---|---|---|---|---|
| V-ACTIVITIES-01 | Calendar, hint beside the title | «Drag to reschedule · synced calendar events update too» | «Drag to reschedule» | No calendar is synced until the provider adapters exist (0010); the second half would be untrue |
| V-ACTIVITIES-02 | Calendar, week grid | Monday shaded as today; fixed 08–17 rows | The real today is shaded; rows 08–17 widened to every hour that holds an activity; an all-day row appears when the week has all-day activities | The task's grid rules; the design's «today» is its fixed scenario date |
| V-ACTIVITIES-03 | Calendar, Status filter | «Open» still shows done activities in the calendar (prototype condition) | «Open» shows open activities, «Done» done ones, «All» both, struck through when done | The filter does what it says |
| V-ACTIVITIES-04 | Calendar, navigation | Only the current week/month/day; no previous/next control | The same; `?date=YYYY-MM-DD` selects another period, no control added | Not in the design (no feature invented); the address keeps it reachable |
| V-ACTIVITIES-05 | Calendar, month view | Silently shows the first three activities of a day | First three, then «+N more» | A hidden activity would look like none |
| V-ACTIVITIES-06 | Calendar, day view | Always has rows; «Video link» whenever the type is a meeting | An empty-day line in the design's language; «Video link» only when a link is stored; guest count from stored guests | Never fabricate |
| V-ACTIVITIES-07 | To-do list, tabs | «All 30» includes done activities | «All» lists the open activities and counts them (`activities_get` counts.all = open); «Done» lists the done ones; a done row shows its date, not «N d overdue» | The database's count definition; a done activity is not overdue |
| V-ACTIVITIES-08 | To-do list, Guests column | «N · 1 declined» on every row with guests | The stored guest count, «· N declined» only when stored responses say so, else «—» | Never fabricate (task) |
| V-ACTIVITIES-09 | To-do list, narrow screens | The table is clipped by the card (overflow hidden) | The rows scroll sideways inside the card below 904 px | The 390 px layout must stay usable without page scroll |
| V-ACTIVITIES-10 | Meeting scheduler, booking links | Two fixed links with `book.orgpuls.no/…` addresses | The staff member's stored links; the mono line shows the link's slug only; an empty state and a «New booking link» card (`booking_link_save`) | No public booking page exists yet (D-28), so no address is shown as if it worked; D-41 for the empty/create state |
| V-ACTIVITIES-11 | Meeting scheduler, availability | A default weekly pattern; «Busy times are read from the synced calendar · 15 min buffer · video link added automatically» | The stored availability (empty until set), saved on each toggle; the note says no calendar is connected and slots come only from the marked hours | Never fabricate; no provider busy times yet (task) |
| V-ACTIVITIES-12 | Meeting scheduler, preview | Six fixed slots; Confirm books; «Tor Lambrechts · 30 min · Google Meet» | Slots computed from the stored availability (first six from now within the link's horizon, 30-minute steps); a proposed-times link says its times are not stored; Confirm is disabled with «Preview only …»; the provider only when the link has one | No booking RPC or public page; the schema stores no proposed times (request R-ACT-02) |
| V-ACTIVITIES-13 | Meeting scheduler, recent bookings | Three fixed bookings with organization | Stored bookings (name · link title · time), or «No bookings yet» | Never fabricate; `my_scheduling` returns no organization (request R-ACT-04) |
| V-ACTIVITIES-14 | Reminders, channels | «To tor@…», «Browser permission granted», «iPhone · Sentral mobile» | Email: «To {email} · sent once the email provider is connected»; Desktop: the browser's real permission; Push: «No device registered yet», switch disabled while off | Only in-app reminders are dispatched (`app.dispatch_reminders`); no push device exists (D-38) |
| V-ACTIVITIES-15 | Reminders, calendar sync | Google selected, Two-way, «tor@orgpuls.no / Sales team», «last sync 2 min ago · 0 conflicts» | The not-connected state: provider, mode, calendar and type controls shown disabled, the stored provider highlighted if any; «Not connected · … nothing is synced yet» | No function saves a calendar connection (request R-ACT-01); never fabricate sync status (task) |
| V-ACTIVITIES-16 | Edit dialog, type chips | Includes «Site visit» | The activity types in the database | «Site visit» is not a seeded type; types are data |
| V-ACTIVITIES-17 | Edit dialog, Date and Time | Text inputs («6 Oct 2026», «10:00») | Native date and time inputs, same classes | Control substitution: a text field cannot enforce a valid date or time |
| V-ACTIVITIES-18 | Edit dialog, defaults | Priority «High», deal «Lumio AS — Expansion…», video «Google Meet», reminders In app/Email/Push | Priority medium (database default), no deal, video None, reminders = the staff member's default channels | The design's defaults are the first option or its scenario; never fabricate a link |
| V-ACTIVITIES-19 | Edit dialog, duration | 30/45/60 | 15/30/45/60/90/120 and the stored value | Seeded activities last 15 and 90 minutes |
| V-ACTIVITIES-20 | Edit dialog, guests | Three fixed guests with RSVP; «invites go out through the synced calendar» | Stored guests with their stored response («No answer yet» when none), add by email (people with an email offered), remove; the heading says invites are not sent while no calendar is connected | Never fabricate RSVP lists (task) |
| V-ACTIVITIES-21 | Edit dialog, video link | A generated `meet.google.com/…` address per provider | The provider choice is stored; a link is stored only when typed, the placeholder says the provider is not connected | Never fabricate video links (task) |
| V-ACTIVITIES-22 | Edit dialog, Outcome | «Outcome (custom field)» select | Custom fields of Settings › Data fields for activities (single option and text), limited to the activity type; none are seeded, so none show | Fields are data |
| V-ACTIVITIES-23 | Edit dialog, narrow screens | Date/Time/Duration/Priority in four columns at every width | Two columns under 640 px | Native date inputs do not fit a quarter of 350 px |
| V-ACTIVITIES-24 | Toasts | «Activity saved · invites sent · reminders set», «… · calendar event updated», «Booked … · confirmation sent» | «Activity saved» (+ «· reminders set» when reminders were set), «Rescheduled to Fri 16:00» | Nothing is sent and no calendar event exists |
| V-ACTIVITIES-25 | Next-step prompt | Options only close the prompt | Each option creates the activity on the same deal, person and organization (Call +2 days, Email +1, Meeting +7, Task «Send proposal» +1, at 10:00) | The prompt's purpose; 10:00 is the dialog's default time |
| V-ACTIVITIES-26 | Type names | English everywhere | The seven system types shown in bokmål while their stored name is unchanged; renamed or custom types show their stored name | Data-driven labels through messages |
