# Deviations — Settings (`app/(admin)/settings`, Settings.dc.html)

Same columns as `DEVIATIONS.md`. For the lead builder to fold in.

| ID | Where | Design | Built | Reason |
|---|---|---|---|---|
| V-SETTINGS-01 | Section nav | Buttons that switch a section in place | Links to `/settings?sec=<key>`, same classes | Control substitution (V-01): a section gets an address |
| V-SETTINGS-02 | Every section at 390 px | Two-column grid (200 px nav), which overflows at phone width | The nav becomes a sideways-scrolling row above the section; wide tables scroll inside their card | The design has no phone layout for Settings; built in its language (D-41) |
| V-SETTINGS-03 | Rules and limits | Firewall as the only fixed row | Firewall and second factor (`mfa`) both shown fixed, read-only | The register holds both as fixed (D-11, 0005) |
| V-SETTINGS-04 | Rules and limits, «A number» / «Custom» options | Option pills only | A number field and «Set» pill appear beside the chosen numeric option; the state reads «Changed · A number (50)» | `setting_set` takes the number; a gap in the design built in its language (D-41) |
| V-SETTINGS-05 | Rules and limits, change log | Two fixed rows («1 Oct … kept at default», «3 Oct System … register created») | The real log (`settings_log`: setting and module changes), or «No setting has been changed yet» | Never fabricate |
| V-SETTINGS-06 | Data fields | Seven fixed example fields for Deals | The real definitions (`fields_get`); empty treatment when a record type has none (none are seeded) | Never fabricate |
| V-SETTINGS-07 | Data fields, record-type chips | Deals, Leads, People, Organizations, Products, Projects, Activities | The record types in the registry (read through `sandbox_counts`): Deals, Leads, People, Organizations, Products, Activities, Tickets | Projects has no record type yet; tickets has (0012) |

| V-SETTINGS-09 | Data fields, type count | «Type — 16 available» | «Type — 17 available»: the sixteen plus Formula | The database keeps formula as its own type (CUS-04, 0006); without it no formula field can be made |
| V-SETTINGS-10 | Pipelines, «＋ Pipeline» | Toast only | An inline name field, then `pipeline_save` | A pipeline needs a name |
| V-SETTINGS-11 | Pipelines, delete stage | Deletes at once, moves to the previous stage, counts open deals from demo data | Asks for the target stage (a row under the stage), then `stage_delete`; the toast states the count the database moved (every deal in the stage, not only open ones) | PIP-02 |
| V-SETTINGS-12 | Pipelines, ▲ / ▼ | Always active | ▲ disabled on the first stage, ▼ on the last; «Delete stage» disabled when one stage is left | The database refuses those moves |
| V-SETTINGS-13 | Activity types, custom fields | Fixed strings per row («Outcome, duration» …) | The custom fields on activities that apply to the type (`fields_get('activity')`, `activity_type_ids`), else «—» | Never fabricate (none are seeded, so every row reads «—») |
| V-SETTINGS-14 | Activity types, «＋ Activity type» | Adds a fixed «Site visit ⌂» | A row with glyph and name fields, then `activity_type_save` | A type needs a name |
| V-SETTINGS-15 | Language and currencies, languages | English, Norsk bokmål, Svenska | English and Norsk bokmål | D-04 |

| V-SETTINGS-17 | Language and currencies, currencies | NOK, EUR, SEK, DKK, USD with exchange rates; «＋ Custom currency» active | NOK as the company default only; «＋ Custom currency» disabled with «More currencies arrive with stored exchange rates from Norges Bank» | No currency table; rates would be invented (request R-SETTINGS-01) |
