# Sentral Simple › Customers: deviations from the design

Design: `design-reference/sentral-simple/SimpleCustomers.dc.html` (route `/customers`, tabs «Accounts» and «Tickets and
requests» `?tab=tickets`). Migration `supabase/migrations/0056_simple_customers.sql`, proved by
`supabase/tests/simple_customers_invariants.sql` (30 checks) and `tests/simple-customers.test.ts`.

0056 adds: `app.tickets.request` (a structured service request, `{kind, args}`, kinds extend_trial / change_plan / suspend /
reactivate / cancel / other) filled at intake from a `support.requested` payload's `request`; the `requests` view and
count in `tickets_get`; `customers_get` with a product reports that application's status, plan and MRR; the outcome of
admin rows in `customer_timeline` (reads left out); `simple_customers_summary(product)` for the KPI row.

| ID | Where | Design | Built | Why |
|---|---|---|---|---|
| V-SCU-01 | Accounts › list MRR, KPI MRR/ARR | The account's MRR summed over all its applications (Lumio AS 1 017 kr under Orgpuls) | The selected application's MRR, plan and status (0056 scopes `app.org_customer` when a product is named; «products» still lists every application). «—» when the account pays nothing; the KPI is «—» while no subscription in scope carries a price | The header names the application; a sum across applications would overstate it |
| V-SCU-02 | Accounts › KPI row | «Trial → paid 31 %», «Median first reply 2 h» hard-coded | Trial → paid from `app.v_trial_conversion` (trials started 45–135 days ago, confirmed within 45 days, as Analytics reads 90 days), «—» without trials. Median first reply over 30 days in business minutes, as `ticket_reports`. Open tickets and the median need tickets:see (otherwise «—»). Accounts are the companies the caller may see | Never fabricate; the summary needs no reports right |
| V-SCU-03 | Account › Health | A generated score | `app.org_health` (the lowest latest score of the company's applications), «—» when none | Real source |
| V-SCU-04 | Account › Admin contact | The organisation's first person | The application's billing contact, else its first active daglig_leder/admin/owner, else the first CRM contact, else «—» | Real source |
| V-SCU-05 | Account › Recent | «Admin logged in 2 d ago», «Survey sent to 48 employees», «Signed up · Partner» | The newest five rows of `customer_timeline`: product events, admin actions (with their outcome: «Trial extension failed»), tickets opened; «Nothing recorded yet.» when empty. Locally no product events exist (`events_in` is empty) | The prototype invents them |
| V-SCU-06 | Account › Actions | Change plan, Send login link, Suspend/Reactivate change the account and toast «· saved to the account log» | Disabled, with one line under the grid: «Change plan · Send login link · Suspend: Not available in Orgpuls yet» | Orgpuls has no `billing.change_plan`, `users.send_login_link`, `billing.suspend`/`reactivate` (SIMPLE-PLAN, needs outside the app) |
| V-SCU-07 | Account › Extend trial 14 days | Changes the status locally | Orgpuls `billing.extend_trial` through `runCustomerAction` (14 days, reason «Extended from Sentral», a message key, so it stays one click); the outcome is written to the account log and shows in Recent. Disabled (with the reason) under another application (only Orgpuls takes commands), without an Orgpuls subscription, or without global:edit_others. Locally `product-command` is not served, so it fails honestly («Orgpuls could not be reached») | Real command |
| V-SCU-08 | Ticket › Status select | New, Open, Waiting on customer, Resolved | The schema's six: adds Waiting on us and Closed | A ticket's real status must always be shown |
| V-SCU-09 | Ticket › Priority select | Priority is set directly | Priority is generated from impact × urgency (0012); the select writes the pair that gives it, keeping the current impact where it can, else Urgent = many_orgs+blocking, High = one_user+blocking, Normal = one_org+not_blocking, Low = one_user+not_blocking | The schema derives priority |
| V-SCU-10 | Ticket › Assignee select | Three hard-coded names | `ticket_config` assignees (active staff with tickets:see, or admins) | Real source |
| V-SCU-11 | Composer › Reply | Placeholder «Reply to … — sent by email», toast «Reply sent» | Placeholder «Reply to … — saved in the thread; email delivery is not connected yet», toast «Saved — email delivery is not connected yet»; the thread marks such replies «Reply · not emailed». The button keeps «Send reply» | No mail provider: replies are stored with delivery_status not_configured |
| V-SCU-12 | Composer › Canned reply | Three texts in the prototype | Published macros (`macros_get`, bokmål version), merge fields filled ([fornavn], [organisasjon], [orgnr], [agent]); a reply with a field left ([dager], [dato]) is not saved and the toast names the fields | Real source; the database refuses unfilled fields |
| V-SCU-13 | Request › Approve and apply | Applies any request, resolves it, «The customer has been notified» | Only a structured request of kind extend_trial, for an Orgpuls account in a trial, by someone with global:edit_others: `billing.extend_trial` with the request's days (else 14), a thread line («Trial extended in Orgpuls» / «Orgpuls did not extend the trial»), then the ticket is resolved. The toast says the customer is not told. Otherwise disabled, and the request line says why (no action named, no Orgpuls command, not Orgpuls, no account, not in a trial, no right) | Only one command exists; no mail provider |
| V-SCU-14 | Request › text | The subject, plus «approving applies it to the account» for billing | The structured request in words («Extend the trial by 14 days», «Change plan to 26–100» …) or the subject, then «— approving applies it in Orgpuls» or the reason it cannot | Honest state |
| V-SCU-15 | Request › Decline | Prefills a Norwegian text signed «Tor» | Prefills the reply in the staff member's language (message key), signed with their name | Message keys, real author |
| V-SCU-16 | Tickets › scope | Under Orgpuls every ticket of every application, under others that application's | Every queue is the selected application's tickets (`tickets_get` product). A ticket without an application (created by staff without one) is in no Simple queue; the full Tickets screen still lists it | One rule for every application |
| V-SCU-17 | Ticket › Thread | One synthesised customer message | The stored thread: customer messages, replies, internal notes, action lines and system lines | Real source |
| V-SCU-18 | Lists › order | The data file's order | Accounts by name (`customers_get`); tickets by SLA due (`tickets_get` sort «sla») | The database's orders; the most urgent ticket first |
| V-SCU-19 | Tabs, queue chips, account and ticket rows | Buttons that change state | Links (`?tab=`, `?org=`, `?queue=`, `?ticket=`), so the links other screens use (`/customers?org=…`) open the same account (control substitution, D-06). Search and the status filter stay in the browser, as in the design | The prototype has no router |
| V-SCU-20 | Narrow widths | None drawn (the 244 px rail leaves ~150 px at 390) | The shell's menu replaces the rail; the account list drops the Plan column under md; the ticket detail spans two columns from lg only | The design has no phone layout |
| V-SCU-21 | Rights | Everything enabled | The Accounts tab needs deals:see, the Tickets tab tickets:see; the KPI row either. Ticket fields need the ticket's owner or tickets:edit_others; the composer and Decline also allow the assignee, otherwise the placeholder says who may write | The database refuses anyway |
| V-SCU-22 | Ticket fields | No feedback | No toast on success (as the design); a refusal (e.g. a version conflict) restores the value and shows the error | Honest state |
| V-SCU-23 | Seed | — | `scripts/seed/simple-customers.mjs`: T-2312 `extend_trial` 14 days, T-2321 `change_plan` 26–100, T-2315/T-2324/T-2333 `other`; personvern requests carry none. T-2312's account (Nordlys Logistikk AS) is active in the seed, so its approval shows «the account is not in a trial»; the enabled path is proved by the SQL suite and the unit tests. The shared database is not reset, so until it is, the requests show «it names no action Sentral can apply» | Design data as seeded |
| V-SCU-24 | Intake | — | The brief names `app.ticket_intake_trigger`; the request is set in `app.ticket_intake` (0031 body), which that trigger calls. Payload contract: `support.requested` `{"request": {"kind": "extend_trial", "args": {"days": 14}}}`; only `days` (1–60) and `plan` (≤ 40 characters) are kept, never free text; the request does not reach a platform event | Smallest change on the existing path |
