# Sentral Simple › Platform: deviations

Design: `design-reference/sentral-simple/SimplePlatform.dc.html`. Route `/platform` (`?tab=plans`, `?tab=team`), components in
`app/(admin)/platform/`, loaders in `lib/data/simple-platform.ts`, migration `0057_simple_roles.sql` (suite
`supabase/tests/simple_platform_invariants.sql`), actions tested in `tests/simple-platform.test.ts`.

| ID | Where | Design | Built | Why |
|---|---|---|---|---|
| V-SPL-01 | Tabs | Three pill `<button>`s switching local state | The same pills as links: `/platform`, `/platform?tab=plans`, `/platform?tab=team` | Control substitution: a tab has an address (the prototype has no router) |
| V-SPL-02 | Application card: response, errors, Test connection | «182 ms», «0,2 %» from the seed; the test toasts the seeded latency | `health.p95_ms` / `error_rate`, which are null today → «—» with a note under the cards. Test connection runs `orgs.list` through product-command and toasts the measured time or the product's failure code; the answer is shown, not stored | product-command and orgpuls-events do not log their calls yet (`worker_integration_call`, `worker_application_ping` are the edge functions' and unwired); only Orgpuls has a command path, so the button is disabled for the others with that reason |
| V-SPL-03 | Maintenance mode | Toggle that flips the pill to «Maintenance» and toasts | Disabled, reason under the cards. When a product gains `settings.set_maintenance` the button links to the confirmed flow (owner, fresh second factor, key typed) at `/applications?tab=flags` | No product has the command (D-40, V-P8P-17); never fake it |
| V-SPL-04 | Feature flags | Five invented flags, instant toggles in local state | The product's own question modules, read with `modules.list` after the card opens (not on every render), Orgpuls only. On = published. The switch publishes a draft or retires a published version through `modules.set_status`, in a dialog asking a reason (≥ 5 characters, Orgpuls' audit); a retired version is shown off and locked. Needs global:configure. States: no flag command, reading, the product's failure code with Try again, no modules | Real names only; Orgpuls moves a module draft → published → retired (one way) and requires a reason |
| V-SPL-05 | API key | `sk_live_4f8a…c21e` and Rotate (a new key in one click) | Whether Vault holds the product's token secret and webhook secret (`application_get.connection`), never a value; Rotate disabled; a line says how rotation works (the owner opens a one-time intake number, the product posts its new secrets) | CLAUDE.md rule 5: secrets never shown, never passed through a person; a product-bound intake cannot overwrite an existing secret (0044), so rotation is the operator's unbound intake |
| V-SPL-06 | Status message | Textarea and «Publish to …» that toasts | Stored with `status_notice_set` (as before, which also queues a `product_command` job no worker drains yet), then delivered at once with Orgpuls' `settings.set_notice` (`p_on`, the same text as `p_no` and `p_en`); the outcome is recorded with `status_notice_push_result` (0057: once, by the publisher, within 5 minutes, «delivered» only when the command audit holds the successful call). A status line shows when it was published and whether it reached the product; an existing problem link is kept and named. Added: «Clear» while a message is live. At most 300 characters | Orgpuls' site notice is one bilingual notice of ≤ 300 characters; nothing else delivers the queued job; a message that cannot be cleared from the only screen that sets it would be a trap |
| V-SPL-07 | Plans and prices: editing | Price inputs, trial-length and annual-discount selects, «Save prices» | Read-only: the monthly price in the design's box (not an input), trial length «—», the annual discount derived from the catalogue (`annual_price` against 12 × monthly: «2 months free»), «Save prices» disabled; the footnote says why and from when the prices apply | Orgpuls owns checkout and Sentral has no command for prices, trial or discount (D-40); the trial length is not reported to Sentral |
| V-SPL-08 | Plan cards | Names Small / Medium / Large / Enterprise, «included» lines, the second card outlined | The band as the title («1–25 employees»), its annual price as the second line; no included lines; no outline | `plan_versions` holds bands and prices only; nothing records plan names, entitlements or a recommended plan |
| V-SPL-09 | Plan cards: accounts | Organisations in the band | `plan_accounts` (0057): accounts whose installation is active and whose subscription is on that band and neither cancelled nor expired (trials included) | The design counts every organisation; a cancelled subscription is not on a plan |
| V-SPL-10 | «＋ Connect an application» | Toast «Add the base URL and API key …» | The Platform screen's connect dialog (owner, fresh second factor, an intake code bound to the new key); for anyone else the tile is disabled and says only the owner can | 0044 `application_connect`; no key is typed into Sentral |
| V-SPL-11 | Roles | Select of Admin / Sales / Support / Marketing / Read-only; the seed's roles mapped in the browser | 0057: the sets admin, sales, support, marketing, analyst renamed to the five roles; Marketing += campaigns:reports_others, campaigns:workflows, campaigns:delete, global:see; Sales += campaigns:see, campaigns:add (CRM › Lists); Finance and Projects kept but `offered = false`, their members moved (finance → Read-only, project → Sales, audited `staff.role_folded`). The select offers only offered sets (a custom set by its name); someone on a set that is not offered sees it as a locked extra option. The owner shows «Admin (owner)», locked (staff_save refuses `owner`); one's own row is locked (`self`); without global:security every control is disabled with a line saying so | The design's own map (RM); the database refuses what the screen hides |
| V-SPL-12 | Invite | Adds a row «Invited» and toasts «Invite sent to …» | `staff_save` with the address only: a staff row on Read-only, no name made up from the address, no Auth user, no e-mail. The toast says no e-mail is sent and that they sign in once an owner has created their login; the row's last activity reads «No login yet» (`staff_list.login`, global:security only) | No mail provider; creating logins stays the owner's (D-11) |
| V-SPL-13 | Last active | «2 days ago» from the seed | `last_seen_at` as a relative time, for global:security holders only (as `staff_list` returns it), «—» otherwise; «Removed» for an inactive person | staff_list hides activity without global:security |
| V-SPL-14 | Remove / Restore | Dims the row locally | `saveStaff({ active })`: deactivation ends the person's sessions at once (0043); their records stay theirs (no reassignment, which is Settings › Replace) | The design's one-click toggle; reassignment has no place in the design |
| V-SPL-15 | Status pill | Operational / Degraded / Beta / Maintenance | The application's health (operational, degraded, unreachable, no data yet, disabled, not connected) in the design's four colour pairs | V-P8P-25: honest states; «Beta» is a stage, not a health |
| V-SPL-16 | Card API line | `api.orgpuls.no/v2 · v2.14.1` | The installation's host and the product's reported API version, «—» until a ping reports it | Seed values |
| V-SPL-17 | Team on a phone | Four columns at every width | Below 640 px «Last active» is hidden and the columns narrow | The design's 160 + 110 + 90 px columns do not fit 390 px |
| V-SPL-18 | Order of the team | The seed's order | `staff_list`'s order: active first, then by name | No stored order |
