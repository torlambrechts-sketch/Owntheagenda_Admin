# Deviations — Tickets

Where the Tickets screen departs from `design-reference/sentral/project/Tickets.dc.html`, and why. Same
columns as `DEVIATIONS.md`; the lead builder folds these in.

| ID | Where | Design | Built | Reason |
|---|---|---|---|---|
| V-TICKETS-01 | Inbox › list | SLA text in whole hours from a random age | «Overdue 12 h», «3 h left», «40 min left» from `first_response_left_min` (business minutes) | Never fabricate: the database computes SLA in business time |
| V-TICKETS-02 | Inbox › thread | Attachment chip «skjermbilde.png · 182 kB»; ▤ Attach button | No chip; Attach disabled with «Attachments arrive with file storage» | No attachment storage exists |
| V-TICKETS-03 | Inbox › thread | System message «Auto-linked … E-mail log: 14 deferred, 451 greylisted» on T-2310 | Not rendered; the thread shows only stored `ticket_messages` | No auto-link or mail log source |
| V-TICKETS-04 | Inbox › composer | Placeholder «… sent by e-mail and threaded»; toast «Reply sent · threaded by e-mail» | «… kept in the thread until e-mail is connected»; toast «Reply saved to the thread · not e-mailed …»; under every reply stored as `not_configured` the line «Not e-mailed: the mail provider is not connected yet …» | The mail provider is not connected (D-07); a reply is stored with delivery_status `not_configured` |
| V-TICKETS-05 | Inbox › SLA box | «Met · 1 h 40 min» | «Met · {first_response_used_min}»; «Late · …» when the first response came after its due time | Never fabricate; the late case is built in the design's language (D-41) |
| V-TICKETS-06 | Inbox › organization card | «931 237 287 · 251–500 · 416 employees», «Health 75», status always | Org.nr and employees; «Health —»; the status chip and the trial/customer chip only when the ticket's product has a subscription | No band or health score source (health is phase 2); no subscription for some products |
| V-TICKETS-07 | Inbox › captured automatically | App version from the product catalogue | `context.app_version`, else «—» | Intake stores it only when the product sends it |
| V-TICKETS-08 | Inbox › links | Survey «Baseline 2026 · metadata only», Invoice «INV-40171», Deal «New business · Qualified» by category | Only stored `ticket_links` (× removes one); «Link survey or invoice» opens a kind/reference/label form; «Link to problem» opens a select of problem tickets | Never fabricate; the forms are built in the design's language (D-41) |
| V-TICKETS-09 | Inbox › service request | Four actions run and post an «Admin action» system message | Extend trial 14 days runs `billing.extend_trial` (p_org, p_days 14, p_reason = T-number) and writes `customer_action_log` with the T-number; it is disabled with «Not in trial» / «Only Orgpuls takes this command» when it cannot run. Change plan, Export organization data, Switch to EHF are disabled «Not available from here yet (D-40)». No thread message: the outcome is a toast and the company's audit trail | D-40; no RPC writes a system message (requests/tickets.md R-1, R-4) |
| V-TICKETS-10 | Inbox › personvern panel | «24 days left» | Days to `privacy_requests.due_at`, or «… overdue» | Never fabricate |
| V-TICKETS-11 | Inbox › escalate | Assigns Tor | Assigns an active super-admin (permission set of kind admin) other than the current holder; disabled when there is none | The super-admin is data |
| V-TICKETS-12 | Inbox › @ Mention | Appends «@Hanna» | A picker of staff; the chosen ids go to `ticket_message` mentions (notes only, as the database notifies) | Built in the design's language (D-41) |
| V-TICKETS-13 | Inbox › composer | After-send select always active | Disabled in Internal note mode | A note never changes the status |
| V-TICKETS-14 | Problems | Owner and workaround fixed; «Resolve and notify» resolves at once; banner toggles | Owner from `owner_id`; «Resolve and notify N» (N = open linked incidents) opens a message box, because `problem_resolve` sends that message as the reply on each incident; the help-centre toggle publishes or unpublishes the article linked to the problem (tickets:configure); the in-app banner toggle shows `status_banner` but is disabled, with the line «Reaches customers when Orgpuls adds a status-banner command (D-40)» | Nothing reads `status_banner` yet (requests/tickets.md R-4) |
| V-TICKETS-15 | Help centre | «Ticket-to-article rate 38 %», views 1 840, deflected 212 «this month» | Rate «—»; views and deflections are 30-day sums of `help_article_stats_daily` (zero in the seed); «Updated» is the article's `updated_at` | No source for the rate (R-5); never fabricate |
| V-TICKETS-16 | Help centre › widget | «Still need help? Send to support» without an action | Opens the new-ticket dialog with the query as subject | Built in the design's language |
| V-TICKETS-17 | Macros | «Bokmål · version 4 · edited in Content management»; buttons inert | «Bokmål · version N»; the text is edited here and «Publish new version» calls `macro_publish` (tickets:configure); «Nynorsk version» switches the editor to the nn versions | There is no Content management screen |
| V-TICKETS-18 | Reports | «within target», «−0,8», «68 % response», «2,1 h / 4 h», «median this month» | Subs that have a source: «Business time», «of N resolved», CSAT answered/requested; durations as «2 h 6 min / 4 h»; «median, last 30 days»; «—» where a value is null | Never fabricate; `ticket_reports` covers the last 30 days |
| V-TICKETS-19 | SLA and routing | Read-only tables | An «Edit» button (tickets:configure) turns the targets into hour fields (`sla_policy_save`) and routing into one queue select per category (`category_route`); business hours come from `ticket_config` | Built in the design's language |
| V-TICKETS-20 | SLA and routing › channels | Contact form «creates … a CRM prospect if consent is given»; e-mail «Converted to tickets; replies are threaded» | «… the CRM prospect arrives with lead capture»; «… once the mail provider is connected» | Lead creation from contact.submitted comes with phase 5; mail is not connected |
| V-TICKETS-21 | New ticket dialog | Organization, Category, Subject, Description; «Contact-form tickets also create a CRM prospect if consented»; toast «Ticket T-2334 created · routed to Support» | A Contact select (people of the chosen company) is added; that sentence is left out; the toast carries the real ref and queue; Create is disabled until a subject is typed; the new ticket opens unless its queue is closed to the staff member | `ticket_create` takes person_id; the prospect claim is phase 5 |
| V-TICKETS-22 | Tabs at 390 px | Macros grid 240–320 px + rest; tables with fixed columns | Macros stack below md; the articles table scrolls inside its card | No horizontal page scroll at phone width |
| V-TICKETS-23 | Reports tab | Shown to everyone | Hidden without tickets:reports_others; the Personvern chip is hidden when the queue's `allowed` is false | Rights: hide what the staff member may not use |
